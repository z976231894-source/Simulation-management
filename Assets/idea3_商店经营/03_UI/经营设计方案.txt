ONE MORE DINER · 纯餐厅经营方案 v1

定位
单店、第一人称、轻操作的餐厅经营游戏。复用当前餐厅、厨房与低模人物外观。人物只代表普通顾客，不沿用原剧情、记忆服务、重逢、支付记忆或两个结局。所有玩家可见文字保持英文。本文件与配套图片是新玩法设计稿，本轮未改动现有网页版运行逻辑。

玩家目标
把这家小餐厅经营得更赚钱、更从容。每个营业日先选菜单和备货，营业时处理少量并行订单，闭店后判断哪里浪费了钱，再决定升级。深度来自库存、菜单价格、产能和顾客等待的取舍，不依靠新增复杂人物动画。

最小完整经营循环
1. 开店前：看预计客流与订单比例，检查剩余食材，选择采购量与菜单价格。采购后显示剩余现金，并提醒最低可售份数；货不足可以少买、少开几种菜。
2. 营业中：顾客到桌后生成订单，最多三桌并行。选订单、烤制、点选配料、装盘送桌。交付即自动收款，不加找零或收银动作。顾客耐心清楚可见；可先完成快单，也可先救快超时的单。
3. 营业结束：停止新增顾客，允许处理已接受的订单。显示营业额、食材成本、固定开支、浪费和净利润，不把收入当利润。
4. 次日准备：用现金采购或升级，同一笔钱不能两头使用。继续营业，观察新配置是否改善利润与等待情况。

一单的操作
从食材架拿料 → 放到烤台 → 取出并选择配方 → 装盘 → 送到桌上。
配料用一次菜单选择完成，制作时切换模型状态即可。首版只有未烤、烤好、过烤三种结果，不加翻锅、揉面、切菜、摆手付钱等 K 动画。送餐和食材搬运复用走路与持物动作；顾客复用坐姿、等待和简短反馈。
烤好后可短时放在出餐位，等待另一单；过烤允许丢弃重做。装错餐可放回出餐位修改。送到错误桌不会自动收钱，也不会静默通过。

经营数值草案（需试玩调平衡）
每天约 8—10 分钟、约 12 单，三桌并行。初始现金 $200，每日固定开支 $35。
食材单价：Bread $3，Patty $6，Onion portion $1。
Classic Burger：面包1、肉饼1、洋葱1；成本$10，售价$18，单份毛利$8。
Onion Burger：面包1、肉饼1、洋葱2；成本$11，售价$22，单份毛利$11。
Double Burger：面包1、肉饼2、洋葱1；成本$16，售价$28，单份毛利$12。
这里的价格、成本与耐心都是虚构游戏数值。不能把预计收入当作可以提前支付采购的钱。

有意思的取舍
Double Burger 毛利更高，却用两份肉饼；肉饼不足时需要限制它的份数，避免更简单的订单也做不了。
备货多会占用升级资金，并带来隔夜损耗；备货少会少卖几单。预计客流只是估计，下一天可以根据真实销售调整。
加价提高单份毛利但降低客流；降价要有足够食材和烤位，不设置“任何时候加价都更优”的策略。
顾客有不同耐心与菜单偏好，仅通过订单和简短反馈表现，不写熟客故事线。笑点来自古怪外观、菜单名字和经营事故，例如有人点双层，却声称自己只是垫一下肚子。

升级与成本
Cold Storage $100：降低隔夜食材损耗，适合经常备多的人。
Second Grill Slot $120：解锁第二烤位，适合订单排队多的人；购买前第二格标注 Locked，不能同时假装已经可用。
Comfortable Seats $150：延长等候容忍，适合经常送迟的人。
每项升级必须改变下一天的实际策略；不添加只涨数字的无意义等级。
首版不加入多店、员工排班、复杂装修评分、农场供应链或外卖城市地图。现有店内桌数可从两桌开放到三桌，不需要扩建新场景。

失败与恢复
缺货：把菜标为 Sold Out，可推荐已有菜或取消未开始的单。
错餐：回出餐位调整，或退款，不直接重开整天。
客人超时：离开且不付款；UI 说明原因，避免隐藏扣分。
亏损：下一天可以缩小菜单、减少采购；升级与已解锁配方保留。现金不足以营业时提供一笔有明确偿还条件的小额游戏内周转，不用现实购买或广告复活。

UI 新结构
营业 HUD：订单队列、桌号、耐心和出餐状态最突出；顶部显示 Day / Time / Cash，左侧显示食材余量与烤位。中央保留食物操作空间。不能再出现原版费用确认、记忆纸条、重逢字幕或故事结局。
开店界面：预计需求、菜单售价/成本/毛利、采购数量/总额、采购后现金。信息要能支持“买多少、卖什么”的决定。
闭店界面：净利润为核心，营业额、食材、浪费、退款、固定开支能相互对账；升级选项并列，先选再确认，余额不足给出明确原因。
其余必要页面：主菜单与存档、配方列表、设备升级详情、暂停与设置。字体、按钮与纸张样式沿用已有设计系统，内容围绕经营重新组织。

首版验证目标
连续几个营业日能体验“判断需求 → 提高出餐效率 → 发现利润变化”，无需新增地图。
至少存在备货、定价、升级三种有效选择，不应有单一最优菜单。
过烤、缺货、错餐都可理解并恢复，不因一个失误让整天作废。
先用约 7—10 个营业日覆盖解锁与升级变化，再允许持续经营。后续扩展优先加配方与客人偏好，不增加动作制作负担。
